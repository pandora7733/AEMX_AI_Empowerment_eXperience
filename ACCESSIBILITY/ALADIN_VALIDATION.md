# 알라딘 로그인 코드 검증 (2026-09-27)

대상: `feature/accessibility`, Android 16/API 36 x86_64 에뮬레이터 `AEMX_TTS_API_36`.

## 확인한 사실

- Google Play의 [알라딘 인터넷서점](https://play.google.com/store/apps/details?id=kr.co.aladin.third_shop) 앱(`kr.co.aladin.third_shop`, 설치 버전 `2026.8.0`)을 설치했다.
- 홈 화면에서 직접 실행해도 시작 화면 후 앱이 종료되어 로그인 폼에 도달하지 못했다. 앱 로그에는 시작 중 `RetrofitManager.getProperty`의 `NullPointerException` 및 창 종료 관련 기록이 있다. 에뮬레이터, Android 버전, 앱 자체 동작 중 어느 것이 근본 원인인지는 이 기록만으로 확정하지 않는다.
- 사용자는 알라딘 계정이 없으며 이번에는 코드 검증만 요청했다. 실제 계정 로그인 성공, 로그인 폼의 실제 노드 구조, 서버의 인증 결과는 검증하지 않았다. 임의의 아이디·비밀번호로 인증 요청을 보내지 않았다.

## 변경 및 검증

- 알라딘 폼의 아이디 칸에 라벨이 없더라도, 같은 패키지의 편집 가능한 일반 칸 하나·비밀번호 칸 하나·정확히 하나의 명시적 로그인 버튼이 함께 있을 때만 입력칸을 식별하도록 보수적인 대체 규칙을 추가했다. 실제 알라딘 폼에서 관찰한 규칙이 아니므로 모의 화면 단위 검사 결과로만 기록한다.
- 앱 화면이 잠깐 나타났다 사라져도 `open_app`을 완료로 처리하지 않도록 전면 유지 시간을 확인한다. 제한 시간 안에 유지되지 않으면 앱 종료·접근 차단 여부를 확인하라는 메시지로 중단하며 뒤따르는 credential 입력 단계는 실행하지 않는다.
- 단위 테스트 33개, 앱·외부 검사 앱 빌드 및 양쪽 정적 검사에 성공했다. API 36 에뮬레이터의 별도 프로세스 `aladin_open` 검사에서도 서비스 연결과 시작 실패 메시지를 확인했다. 결과는 `PASS: Aladin startup failure reported without credential submission`이었다.

실제 로그인 성공을 검증하려면 알라딘 앱이 정상적으로 로그인 폼을 표시하는 기기와 사용자가 직접 등록한 계정이 필요하다. 그때 폼 식별자와 인증 성공 화면을 확인해 규칙을 조정해야 한다.
