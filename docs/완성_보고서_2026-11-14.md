- 홈 화면의 디버깅 모드와 실시간 패널

단위 테스트는 931개가 모두 통과했다. 이번 작업으로 새로 쓴 테스트는 약 60개다. 모든 기능을 태블릿(레노버 TB520FU, 스냅드래곤 8 Gen 3, 안드로이드 16)에서 직접 실행해 확인했다.

브랜치 상태는 다음과 같다.

## 기능 명세

### 디버깅 모드와 실시간 패널

홈 화면 맨 아래의 "디버깅 모드" 스위치를 켜면 그 아래에 패널이 붙는다. 스위치 상태는 저장되어 다음 실행에도 이어진다. 인식된 말이 화면에 그대로 보이므로 디버그 빌드에서만 스위치가 나온다.

하드웨어 사용량은 1초마다 다시 잰다.

| 항목 | 표시 | 출처 |
| --- | --- | --- |
| 앱 CPU | 전체 코어 대비 막대와 "25% (코어 0.3개 / 8개)" | Process.getElapsedCpuTime 의 차이 |
| 코어 클럭 | 코어마다 칸을 나눠 최대 클럭 대비 막대와 현재 MHz | /sys/devices/system/cpu 의 클럭 파일 |
| 앱 메모리 | 기기 전체 대비 막대, 실사용 MB, 네이티브 힙과 자바 힙 | /proc/self/status, Debug, Runtime |
| 기기 메모리 | 사용량 막대, 사용과 남은 MB. 85% 를 넘으면 주황 | ActivityManager.getMemoryInfo |
| 배터리 | 전류, 전압, 온도 | BatteryManager |
| 발열 | CPU 와 GPU 온도, 시스템 발열 단계 | /sys/class/thermal, PowerManager |
| 음성 안내 (TTS) | 준비됨, 엔진 없음, 한국어 음성 없음 등과 엔진 이름 | TtsStatus |

음성 인식은 100ms 마다 갱신한다.

| 항목 | 표시 |
| --- | --- |
| 언어 | 한국어 모델(언어 감지는 없다) |
| VAD | 문 열림과 닫힘, 소리 크기와 문턱, 소리 크기 막대 |
| 지금 문장 | 말하는 중인 문장의 중간 결과 |
| 단어 | 지금 문장을 띄어쓰기로 나눈 목록과 개수 |
| 끝난 문장 | 최근 8개, 새것이 위 |

음성 줄은 호출어 문을 지나기 전의 원본 인식 결과를 보여 준다. 메모리에만 두고 로그나 파일에 남기지 않으며, 모드를 끄면 지운다.

읽을 수 없는 항목이 있다. 기기 전체 CPU 사용률과 GPU 사용률은 안드로이드 8 이후 일반 앱에 막혀 있어 넣지 않았다. 코어 클럭과 온도 센서는 제조사가 파일을 막아 둔 기기에서는 "읽을 수 없음"으로 나온다.

관련 파일은 debug/DebugPanelView.kt, debug/HardwareMonitor.kt, debug/HardwareStats.kt, debug/SpeechTrace.kt 다.

### 접근성 버튼의 빠른 메뉴

화면에 떠 있는 접근성 버튼은 원래 누르면 시스템이 접근성 서비스를 꺼 버렸다. 이제 앱이 누름을 직접 받아 화면 가운데에 세 칸짜리 메뉴를 띄운다. 바깥을 누르거나 "닫기"를 누르면 닫히고, 20초 동안 손대지 않으면 스스로 닫힌다.

| 칸 | 동작 |
| --- | --- |
| 앱 열기 | AEMX 홈 화면을 앞으로 가져온다 |
| 마이크 | 상태를 점 색(초록 켜짐, 회색 꺼짐, 주황 소리 안 들어옴, 파랑 켜는 중)과 소리 크기 막대로 보여 준다. 누르면 잠시 끄거나 다시 켠다 |
| 완전히 종료 | 두 번 눌러야 한다. 실행 중인 계획을 멈추고 마이크, 듣기 서비스, 알림, 화면을 내린 뒤 프로세스를 끝낸다 |

마이크를 잠시 끈 상태는 저장하지 않는다. 앱을 열어도 꺼진 채 유지되고, 메뉴나 홈의 마이크 버튼으로 다시 켜면 풀린다. 듣기 서비스는 내리지 않아서 다른 앱이 앞에 있어도 다시 켤 수 있다.

완전히 종료는 접근성 서비스 설정을 끄지 않는다. 그래서 안드로이드가 접근성 서비스용 프로세스(약 43MB)를 다시 띄우지만, 그 프로세스는 마이크도 모델도 올리지 않는다. 사용자가 앱을 열거나 마이크를 켤 때까지 듣기는 켜지지 않는다. 부팅하거나 앱을 업데이트하면 이 상태는 풀린다.

관련 파일은 assistant/overlay/QuickMenuController.kt, assistant/overlay/QuickMenu.kt, accessibility/AemxAccessibilityService.kt, pipeline/app/VoiceAutoStart.kt 다.

### TTS 상태 알림

안내 음성이 나오지 않을 때 이유가 겉으로 드러나지 않던 것을 고쳤다. TTS 상태가 바뀔 때마다 AemxTts 태그로 로그를 남기고, 디버깅 패널에 "음성 안내 (TTS)" 줄로 보여 준다. 엔진을 켜지 못했을 때와 한국어를 못 쓸 때는 이유를 따로 적는다. 말하는 내용은 남기지 않는다.

태블릿에서 TTS 가 안 되던 원인은 기기 쪽이었다. 구글 TTS 가 없었고 레노버 엔진은 사용 중지 상태였다. 구글 TTS 를 설치한 뒤에도 기본 엔진 설정이 레노버를 가리켜 연결되지 않았다. 안드로이드는 기본 엔진을 못 쓸 때 시스템에 내장된 엔진만 대신 고르기 때문이다. 기본 엔진을 구글 TTS 로 바꾸자 재생됐다.

다른 기기에서 시연할 때는 TTS 엔진이 설치돼 있고 기본 엔진으로 지정돼 있는지 패널의 TTS 줄로 먼저 확인한다.

관련 파일은 AndroidTtsController.kt 다.

### 쿠팡 검색

"쿠팡에서 생수 검색해줘"가 검색 결과 화면을 바로 연다. 약 2.6초가 걸린다.

쿠팡 앱 주소로 연다. 주소는 coupang://search?keyword=검색어&q=검색어 형식이고, keyword 와 q 를 둘 다 넣어야 결과 화면이 열린다. 하나만 넣으면 빈 검색 입력 화면이 열린다. 웹 주소는 쿠팡 앱이 받지 않는다. 앱 안에서 이어지는 동작이 있어 브라우저로는 넘기지 않는다.

모델이 검색을 "검색칸에 입력하고 검색 누르기"로 풀어 낸 계획은 검색 한 단계로 바로잡는다(SearchShortcutGuard). 바로 검색을 지원하는 앱이고, 사용자가 검색하라고 말했고, 입력 대상이 검색칸을 가리키는 말일 때만 바꾼다. 네이버, 구글, 유튜브 검색에도 같이 적용된다.

관련 파일은 accessibility/SearchRoutes.kt, accessibility/AppLauncher.kt, pipeline/llm/SearchShortcutGuard.kt, LLM/system_prompt.txt 다.

### 쿠팡 장바구니 담기

"쿠팡에서 생수 검색해서 장바구니에 담아줘"가 검색 결과의 첫 상품을 열어 장바구니에 담는다. "두 번째 상품"처럼 순번을 말하면 그 상품을 담는다. 검색부터 담기까지 약 7초가 걸린다.

새 동작 add_to_cart 를 추가했다. 쿠팡에서만 받고, value 는 몇 번째 상품인지다.

실행 순서는 다음과 같다.

- 검색 결과 목록에서 가격이 있는 상품 칸을 위에서부터 세어 N번째를 연다. 목록이 아직 뜨는 중이면 기다린다. 이미 상품 화면이면 그 상품을 담는다.
- 글자가 정확히 "장바구니 담기"인 버튼만, 한 번만 누른다. "바로구매"는 누르지 않는다.
- "장바구니에 상품을 담았습니다" 또는 "담기 완료" 안내, 혹은 장바구니 숫자가 늘어난 것을 확인해야 성공으로 본다. 확인하지 못하면 담았다고 하지 않고 실패로 알린다.

명시했을 때만 담는다. 담기는 사용자의 쿠팡 계정에 실제로 반영되므로 프롬프트에만 맡기지 않고 사용자 말을 코드에서 직접 검사한다(CartGuard).

| 사용자 말 | 담기 실행 |
| --- | --- |
| 쿠팡에서 생수 검색해서 장바구니에 담아줘 | 한다 |
| 생수 장바구니에 넣어줘, 카트에 담아 | 한다 |
| 쿠팡에서 생수 검색해줘 | 하지 않는다 |
| 쿠팡에서 생수 사줘 | 하지 않는다 |
| 쿠팡 장바구니 열어줘, 장바구니 눌러줘 | 하지 않는다 |
| 장바구니에 담지 마 | 하지 않는다 |

기준은 "장바구니"(또는 "카트")와 "담, 넣, 추가"가 함께 있고 부정이 없는 것이다. 모델이 담기 단계를 붙여 냈어도 사용자가 말하지 않았으면 뺀다. 반대로 명시했는데 모델이 빠뜨렸으면 쿠팡 계획에 한해 붙인다.

옵션이 있는 상품은 쿠팡이 묻지 않고 기본으로 골라진 옵션으로 담는다. 시험에서는 티셔츠가 "블랙, 5XL"로 담겼다. 어떤 옵션으로 담겼는지 로그와 증거 문장에 남긴다. 옵션을 음성으로 고르는 기능은 없다.

관련 파일은 accessibility/CartFlow.kt, accessibility/ActionExecutor.kt, pipeline/llm/CartGuard.kt 다.

### 기본 검색 앱 설정 (보고서 작성 뒤에 추가)

홈 화면의 "기본 검색 앱" 항목에서 평소에 쓰는 검색 앱을 고른다. "서울 날씨 검색해줘"처럼 앱을 말하지 않은 검색이 고른 앱으로 간다. 고른 적이 없으면 지금까지처럼 네이버다. 설정은 저장되고 다음 명령부터 바로 적용된다.

고를 수 있는 앱은 네이버, 구글, 크롬, 기기 기본 브라우저다. 선택 창에는 그 기기에 설치된 앱만 나온다. 기기 기본 브라우저는 안드로이드에 기본으로 설정된 브라우저(삼성 인터넷, 제조사 브라우저 등)로 구글 검색 주소를 연다.

| 사용자 말 | 가는 곳 |
| --- | --- |
| 서울 날씨 검색해줘 | 고른 검색 앱 |
| 네이버에서 서울 날씨 검색해줘 | 네이버(설정과 무관) |
| 구글로 찾아줘, 크롬에서 검색해줘 | 말한 앱 |
| 쿠팡에서 생수 검색해줘 | 쿠팡 |
| 고양이 영상 검색해줘 | 모델이 고른 앱(유튜브) |

규칙은 DefaultSearchGuard 에 있다. 계획이 웹 검색(네이버, 구글, 크롬, 기본 브라우저)이고 사용자 말에 검색 앱 이름이 하나도 없을 때만 바꾼다. "구글 주가 검색해줘"처럼 검색어인지 앱인지 애매한 말은 건드리지 않는다.

쿠팡은 함께 본다. 쿠팡을 말하지 않았는데 모델이 쿠팡에서 검색하는 계획을 내는 일이 있었다("부산 맛집 찾아줘"를 쿠팡에서 검색). 쿠팡이라고 말하지 않았고 장바구니 담기도 없는 단순 검색이면 고른 검색 앱으로 보낸다.

태블릿에서 네이버, 크롬, 기기 기본 브라우저로 바꿔 가며 확인했다. 구글 앱은 태블릿에 설치돼 있지 않아 구글 선택은 확인하지 못했다.

관련 파일은 pipeline/llm/DefaultSearchGuard.kt, pipeline/app/PipelineSettings.kt, accessibility/AppLauncher.kt, accessibility/SearchRoutes.kt, MainActivity.kt 다.

## 재검증에서 찾아 고친 문제

두 가지를 찾아 고쳤다.

검색 계획이 흔들리는 문제(bbae0c6). 같은 "쿠팡에서 생수 검색해줘"에 모델이 한 번은 검색 대신 스크롤, 입력, 검색 누르기 5단계를 냈고 45.9초 뒤 실패했다. 위의 SearchShortcutGuard 로 바로잡았다. 고친 뒤 6회 연속 성공했지만 그 6회에서는 모델이 정상 계획을 내서, 가드가 계획을 고치는 경로는 태블릿에서 직접 타지 않았다. 실제로 관찰한 실패 계획으로 만든 단위 테스트로 확인했다.

담기 완료 문구를 놓치는 문제(53af526). 할인 상품은 안내가 "5,510원 할인받고 담기 완료"로 나와 판정 문구에 걸리지 않았다. 숫자가 늘어서 성공으로 처리됐지만, 이미 담긴 상품을 또 담으면 숫자가 오르지 않아 실패로 잘못 알릴 수 있었다. 문구를 추가했고 같은 상품을 다시 담아 확인했다.

## 남은 한계와 확인하지 못한 것

- 음성 경로. 쿠팡 기능은 모두 글자 명령으로 시험했다. 호출어와 음성 인식을 거친 경우는 확인하지 않았다.
- 옵션 선택. 옵션이 있는 상품은 기본 옵션으로 담긴다. 사용자가 원하는 옵션과 다를 수 있다.
- 담기 첫 시도 실패 1회. 처음 구현했을 때 한 번, 상품 칸을 못 찾아 재분석으로 넘어가 58초가 걸렸다. 이후 5번은 첫 시도에 성공했고 원인은 특정하지 못했다. 다시 생기면 볼 수 있게 진단 로그를 넣어 두었다.
- 화면 밖 상품. 순번은 화면에 보이는 상품 칸만 센다. 스크롤해야 보이는 순번은 담지 못한다.
- 완전히 종료 직후 메뉴에서 마이크 켜기. 안드로이드가 백그라운드에서 마이크 서비스를 올리는 것을 막을 수 있어 "앱을 열어서 켜 주세요"로 안내하게 했지만 실제로 눌러 보지는 않았다.
- 다른 기기. 확인한 기기는 태블릿 한 대다.

이번 작업 이전부터 있던 문제도 두 가지 보였다. 고치지 않았다.

- 단계가 실패하면 재분석이 "아래로 스크롤"만 하는 계획을 내고 그것이 끝나면 성공으로 기록되는 경우가 있다.
- "쿠팡 장바구니 열어줘"는 "쿠팡 장바구니"를 앱 이름으로 읽어 실패한다. 담기는 가드가 막아 실행되지 않는다.

## 시험 중 바뀐 것

사용자 쿠팡 장바구니에 시험용 상품이 담겼다. 필요 없으면 지운다.

- 평창수 무라벨 생수 2L 12개, 여러 번
- 물티슈 검색 결과의 첫 상품
- 생수 검색 결과의 두 번째 상품
- 반팔 티셔츠 검색 결과의 첫 상품(블랙, 5XL), 2번

태블릿 설정도 두 가지 바꿨다.

- 구글 "Speech Recognition & Synthesis"를 플레이 스토어에서 설치했다.
- 기본 TTS 엔진을 레노버에서 구글 TTS 로 바꿨다.
